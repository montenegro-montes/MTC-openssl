# Progressive Compact Merkle Authentication laboratory

## 1. Objective

This laboratory tests whether nodes authenticated during one Compact Merkle
credential verification can reduce the proof sent for another credential under
the same signed root. Its primary question is communication benefit after an
exact client-state advertisement has been counted. It does not claim that PCMA
is deployable or faster than TLS.

## 2. Relationship to Compact cold and warm

The current implementation is defined by `src/compact/prepare.py`,
`src/integration/mt_wire.c`, `src/compact/compact.c`, `src/compact/patch.py`, and
`src/compact/scenarios.py`.

`src/compact/prepare.py:credential()` encodes `MTC2`: DNS identity, validity,
SHA-256 of DER SPKI, and serverAuth purpose. `tree()` hashes leaves as
`SHA-256(00 || credential)`, parents as `SHA-256(01 || left || right)`, and
duplicates an unpaired right node. It emits one complete `MTP1` proof per leaf.
`MTP1` contains magic, leaf count, leaf index, root, depth, and every 32-byte
sibling. The authority signs the 88-byte `MTR2` header; `root.signed` appends a
two-byte signature length and the signature.

`compact.c` registers private TLS extension `0xffa6`. The client offers version
2 and cold mode, or warm mode plus a 32-byte root. The server returns an `MCB2`
bundle in EncryptedExtensions. Cold appends `root.signed`; warm omits it because
the client loaded and verified it before the handshake. Both modes still send a
complete `MTP1`. `bundle_decode()`, `root_decode()`, `credential_verify()`, and
`mt_proof_verify()` enforce framing, authority/root, identity, validity, SPKI,
and inclusion. TLS RPK carries the actual SPKI and normal CertificateVerify
proves private-key possession.

`pq-compact-cold` therefore moves signed-root distribution into every
handshake. `pq-compact-warm` preloads only the signed root. The measurement
driver starts a fresh `s_client` for each sample, so warm mode has no persistent
proof-node cache. Its root setup time is recorded separately.

## 3. Prototype architecture

Stage A reads the actual `credential-*.bin` and `proof-*.bin` files generated by
Compact. It verifies every source MTP1 before simulation. After each successful
MTP2 reconstruction it stores authenticated nodes as:

```text
(root[32], level[1], node_index[4], hash[32]) = 69 bytes
```

The root is part of every cache key, so state cannot cross roots. The cache
includes authenticated sibling and computed path nodes below the trusted root.
The root itself remains configured trust state rather than a cached trust
anchor.

Two bounded policies are available: `lru` and `upper-level`, which evicts the
lowest-level nodes first. `full` is unbounded. Cache budgets are enforced using
the 69-byte serialized record size and reports include node count and bytes.

## 4. Implemented functionality

- real MTP1 parsing and verification;
- experimental MTP2 partial-proof encoding and reconstruction;
- exact PCA1 state-advertisement encoding;
- full, zero-size, LRU, and upper-level cache configurations;
- uniform, Zipf-like, clustered, and targeted deterministic workloads;
- single-run and full-matrix drivers with immutable output directories;
- CSV aggregation, Pareto data, plots, negative tests, and wire-size bounds.

## 5. Simulation and TLS boundary

Classification: **B. Stage-A plus a partial-proof protocol implementation**.
MTP2 and PCA1 have exact byte encodings and executable verification, but they
are not integrated into TLS. There is no `pq-compact-pcma` TLS scenario. Existing
Compact cold/warm code, OpenSSL patches, Docker images, and measurement drivers
are unchanged. [`STAGE_B.md`](STAGE_B.md) defines the later integration work.

inspect the diagnostic before choosing the full access count. Use
`--no-include-full-cache` only when a separate full-cache series is unnecessary.

## 16. Metrics

Each observation records timestamp, Git commit, implementation/wire versions,
N, t, leaf, workload, seed, policy, budget, normal/reused/transmitted hashes,
MTP1 baseline bytes, MTP2 bytes, PCA1 bytes, their summed authentication bytes,
net saving and percentage, cache nodes/bytes and cumulative hits/misses. It also
records local proof-construction and reconstruction nanoseconds. These timers
measure Python simulation only.

`net_bytes_saved = normal_proof_bytes - (pcma_proof_bytes +
state_advertisement_bytes)`. Credential, RPK, CertificateVerify, records, TCP,
and root distribution are outside this Stage-A proof-only comparison.

## 17. Reproducibility

Every run records the absolute fixture manifest, seed, complete configuration,
current Git commit, timestamp, protocol version, row count, and SHA-256 of raw
CSV output. Random workloads use a local seeded generator. The fixture manifest
records the actual root and signed-root digest for every N.

## 18. Security limitations

Cached nodes never authenticate alone. MTP2 reconstruction must finish at the
explicit currently trusted root. Root mismatch, missing nodes, malformed
bitmaps, ambiguous lengths, noncanonical odd-node duplication, and altered
hashes fail. Real Compact credential-to-SPKI and CertificateVerify checks are
not reimplemented as TLS here; Stage A begins with real credentials and verifies
their inclusion only. Root updates, revocation, rollback, concurrent cache
writes, and fallback are not implemented.

## 19. Privacy limitations

PCA1 exposes the exact set of cached `(level,index)` positions for one root.
That can reveal access history or subtrees, support fingerprinting and
linkability, and allow cache probing. The prototype intentionally counts this
encoding rather than treating advertisement as free. Compression or private
set techniques are future designs and could add CPU, bytes, or new leakage.

## 20. Known limitations and theoretical bound

MTP1 is unchanged. MTP2 uses a depth bitmap; bit one means server-supplied and
zero requires the corresponding root-scoped cache node. PCA1 lists all cached
positions, while the optimistic bound below assumes a selective advertisement
containing exactly the `depth` required positions. Actual full-cache PCA1 can
be much larger and may erase the benefit.

| N | MTP1 bytes | maximum reusable hash bytes | minimum MTP2 | minimum selective PCA1 | theoretical net saving |
|---:|---:|---:|---:|---:|---:|
| 16 | 173 | 128 | 47 | 58 | 68 B (39.3%) |
| 64 | 237 | 192 | 47 | 68 | 122 B (51.5%) |
| 256 | 301 | 256 | 47 | 78 | 176 B (58.5%) |
| 1024 | 365 | 320 | 48 | 88 | 229 B (62.7%) |

Generate the machine-readable table without running a campaign:

```sh
python3 campaigns/historical_campaigns/pcma/theoretical.py \
  --output /tmp/pcma-theoretical.csv
```

The bound shows that proof reuse is potentially material, but only with a small
or selective advertisement. The complete Stage-A measurements should be run
before any native TLS implementation is recommended.
